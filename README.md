# StratumSS

**A human-readable, utility-first CSS framework with a build-time compiler.**

Class names read like the CSS they produce. The compiler scans your source files
and writes a stylesheet containing only the utilities you actually used.

## Why StratumSS

Most utility frameworks compress their vocabulary (`p-4`, `d-flex`, `ai-center`).
StratumSS keeps it spelled out:

| You write | You get |
| --- | --- |
| `padding-16px` | `padding: 16px` |
| `items-vertical-center` | `align-items: center` |
| `margin-inline-auto` | `margin-inline: auto` |
| `background-color-#0f172a` | `background-color: #0f172a` |
| `padding-10px_24px` | `padding: 10px 24px` |
| `margin-left-neg-4px` | `margin-left: -4px` |
| `color-black!` | `color: black !important` |

Two things separate it from hand-written CSS:

- **Values are validated.** `padding-4p`, `vertical-align-midle` and a `calc()` the
  browser would drop all fail the build with a suggestion instead of quietly
  shipping a broken declaration.
- **Only what you use is emitted.** One class in your markup, one rule in the file.

## Install

```bash
npm install --save-dev stratumss
```

```bash
npx stratumss build src --output public/stratum.css
```

Or run it without installing:

```bash
npx stratumss build
```

Requires Node 20 or newer. The published package ships compiled JavaScript, so no
build step is needed after install.

## Quick start

```bash
# 1. add the stylesheet link to your page
#    <link rel="stylesheet" href="/stratum.css">

# 2. write markup with readable classes
cat > index.html <<'HTML'
<section class="flex flex-direction-column gap-24px padding-32px">
  <h1 class="font-size-40px font-weight-800">StratumSS</h1>
  <p class="color-#475569 line-height-1.6">Readable utilities, verified values.</p>
</section>
HTML

# 3. compile
npx stratumss build . --output stratum.css
```

The generated file (8 utilities from 1 file, 404 B):

```css
/*! StratumSS v1.1.0 — generated by the StratumSS compiler. Do not edit. */

.flex {
    display: flex;
}

.flex-direction-column {
    flex-direction: column;
}

.gap-24px {
    gap: 24px;
}

.padding-32px {
    padding: 32px;
}

.color-\#475569 {
    color: #475569;
}

.font-size-40px {
    font-size: 40px;
}

.font-weight-800 {
    font-weight: 800;
}

.line-height-1\.6 {
    line-height: 1.6;
}
```

Characters that are not valid in a CSS selector (`#`, `.`, `%`, a leading digit)
are escaped automatically; the class name in your markup is unchanged.

## Try it without a build step

`cdn/stratum.css` is every utility that carries no value — 365 rules, 20 kB,
3.3 kB gzipped — regenerated from the same table the compiler uses
(`npm run cdn`, and `npm test` fails if the committed copy drifts). It needs no Node:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/reubqnL/StratumSS@v1.1.0/cdn/stratum.css">
```

jsDelivr serves any file from a public GitHub repository. Pin a tag or a commit rather
than a branch: jsDelivr caches tagged files for a year and branches for 12 hours, so
`@main` serves whoever happened to request it first that day. `examples/cdn.html` is a
page built entirely from those 365 classes — run `npm run demo` and open
`/examples/cdn.html` to see the vocabulary with nothing else loaded.

What is deliberately absent is anything whose name contains a value: `padding-16px`,
`color-#0f172a`, `gap-24px`. There is no fixed set of them to publish until the project
picks a scale, so a linked stylesheet cannot carry them. Spacing, colour and type
therefore need the compiler below.

## Install it from Git instead of npm

npm can install a package straight from a repository, which needs no registry entry at
all — `prepare` runs `tsc` on install, so `dist/` and the `stratumss` command arrive
ready to use:

```bash
npm install --save-dev github:reubqnL/StratumSS#v1.1.0
npx stratumss build src --output public/stratum.css
```

The `#ref` accepts a tag, a branch or a commit; a tag or commit is immutable, so
reinstalling a build later gives you the same bytes. The trade is that installs need
`git` and the devDependencies, and you lose the registry's integrity metadata and
semver range resolution.

## CLI

```
stratumss build [sources...] [options]
stratumss list [options]
stratumss help
stratumss --version
```

| Option | Description |
| --- | --- |
| `-s, --source <path>` | Directory or file to scan (repeatable, defaults to `.`) |
| `-o, --output <file>` | Stylesheet to write (default `./dist/stratum.css`) |
| `--exclude <names>` | Extra directory names to skip, comma separated |
| `--extensions <list>` | File extensions to scan, comma separated (default: html, php, vue, svelte, astro, jsx/tsx, md, and other markup) |
| `--minify` | Emit compact CSS |
| `--no-header` | Omit the banner comment |
| `-w, --watch` | Rebuild whenever a scanned file changes |
| `--allow-unknown` | Warn about unknown classes instead of failing the build |
| `-q, --quiet` | Suppress the build summary |
| `--json` | Print build statistics as JSON |

Builds are **reproducible** (no timestamps, stable ordering) and **atomic** (a
failed build never leaves a half-written stylesheet behind). Unknown classes are
all reported at once, each with its file, line, and a suggestion:

```text
$ npx stratumss build src
error: src/card.html:1: Invalid value in class "padding-4p": "4p" is not a valid length value — expected a number with a unit (px, rem, %, vh, …) or a keyword such as auto
error: src/index.html:1: Unknown StratumSS class "paddign-4px"
    did you mean "padding-4px" or "padding-top-4px"?
error: src/hero.html:3: Invalid value in class "vertical-align-midle": did you mean "vertical-align-middle"?
StratumSS found 3 errors.
```

## How it works

```text
source files ──▶ scanner ──▶ parser ──▶ generator ──▶ stratum.css
                (find the     (validate  (escape
                 classes)      values)    selectors)
```

1. **Scanner** walks the source tree, ignores `node_modules`, `.git`, `dist` and other
   build directories, and reads the `class` / `className` attributes of real tags.
   Comments, `<script>` blocks, prose, and runtime-built class lists are skipped.
2. **Parser** looks each class up in a single utility table, resolves the most
   specific match, and validates the value against the expected shape.
3. **Generator** escapes the class name for the selector, orders declarations by a
   cascade rank, de-duplicates, and writes the stylesheet atomically.

Because the table is the single source of truth, `stratumss list` and the
[generated reference](https://github.com/reubqnL/StratumSS/blob/main/docs/utilities.md) always match what
the compiler accepts.

## Class syntax

| Syntax | Meaning | Example |
| --- | --- | --- |
| `utility-value` | The common case | `padding-16px` |
| `utility-a_b` | Multiple values, joined by a space | `padding-10px_24px` |
| `utility-neg-value` | Negative value, where CSS allows one | `margin-left-neg-4px` |
| `class!` | Marks the declaration `!important` | `color-black!` |
| `var(--x)`, `calc(…)` | Functions are passed through untouched | `width-var(--w)` |
| `_` inside `( … )` | Also a space, so math can be spelled | `width-calc(100%_-_2rem)` |

Values accept the units you expect: `px`, `rem`, `em`, `%`, `vh`, `vw`, `ch`, `fr`,
and so on, plus keywords such as `auto`, `min-content` and `100dvh`.

CSS requires the `+` and `-` inside `calc()`, `min()`, `max()` and `clamp()` to be
space-separated, and a class name has no spaces — so `_` carries them there, and the
value is written out with real spaces. Underscores inside a *function* are never
mistaken for the multi-value separator, and those in a custom-property name are left
alone: `width-min(1px_var(--x))_max-content` is two values, `width-var(--my_color)`
is one. An operator written without its spaces is rejected rather than emitted as a
declaration the browser discards:

```text
error: src/layout.html:12: Invalid value in class "width-calc(100%-2rem)": in calc() the "-" operator needs a space on both sides — write it as "calc(100%_-_2rem)"
```

### Renamed classes

Classes that were renamed before 1.1.0 still compile — the generated selector uses
the name exactly as written, so nothing breaks mid-migration — and the build prints
a warning pointing at the new spelling:

```text
warning: src/index.html:8: "marg-top-4px" is an old class name — use "margin-top-4px" instead
```

Renamed utilities include `marg-*` → `margin-*`, `pad-*` → `padding-*`,
`fdirection-*` → `flex-direction-*`, `fgrow-*` → `flex-grow-*`, `p-abs` →
`position-absolute`, `zindex-*` → `z-index-*`, `insetin-*` → `inset-inline-*`, and
`fwrap` / `fnowrap` / `fwraprev` → `flex-wrap-*`.

## JavaScript API

```js
import { compile, writeResult, parseClass, listUtilityClasses } from 'stratumss';

const result = compile({ sources: ['src'], minify: true });

for (const diagnostic of result.diagnostics) {
    console.error(diagnostic.level, diagnostic.file, diagnostic.line, diagnostic.message);
}

writeResult(result, 'public/stratum.css');

parseClass('items-vertical-center'); // { property: 'align-items', value: 'center', ... }
listUtilityClasses().length;         // every concrete class name in the catalogue
```

| Export | Purpose |
| --- | --- |
| `compile(options)` | Scan + parse + generate, returning CSS, classes and diagnostics |
| `writeResult(result, file)` | Write a result atomically, refusing to write a broken build |
| `formatDiagnostics(list)` | Render diagnostics the way the CLI does |
| `parseClass(name)` | Parse one class; throws `UnknownUtilityError` / `InvalidUtilityValueError` |
| `generateCSS(classes)` | Render parsed classes to CSS |
| `scan(sources)` / `listFiles(sources)` | Find files and extract class occurrences |
| `validateValue(kind, value)` | Validate a value against a utility's expected shape |
| `listUtilityNames()` / `listUtilityClasses()` / `DEFINITIONS` | Introspect the catalogue |

## Development

```bash
npm install
npm run build      # compile TypeScript to dist/
npm test           # build, then run the test suite
npm run docs       # regenerate docs/utilities.md from the utility table
npm run cdn        # regenerate cdn/stratum.css from the utility table
npm run example    # compile examples/index.html to examples/stratum.css
npm run demo       # compile the example and serve it at http://localhost:4173
```

The test suite covers the parser, value validation, the generator's escaping and
ordering, the scanner's ignore rules, the CLI end to end (including watch mode), the
generated reference and stylesheet, and the package manifest npm rewrites while
packing. Every utility in the catalogue is exercised: each declared class and alias
resolves, each enum value round-trips, and no accepted value can break out of its
declaration.
